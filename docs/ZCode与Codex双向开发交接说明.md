# Pen 汉化插件双向开发交接说明

本文用于协调 **ZCode** 与 **Codex** 对 Pen 简体中文汉化项目的修复和开发。两边都可以提出方案、修改实现和复核对方的结果；每次交接都要留下可复现的变更与验证记录，避免只口头同步。

## 1. 项目现状

- 当前仓库位于 `C:\Users\FLEETING\Documents\Project\Chinese localization for Pen`。
- 当前交付是 Windows x64 Pen 的**静态界面汉化补丁**：从原版 `app.asar` 读取资源，替换审核过的固定界面文本，并重建归档索引及完整性数据。
- 目前声明支持 Pen **1.2.10、1.2.13**。支持新版本之前，必须先检查该版本的归档结构、`package.json`、菜单脚本和编辑器资源；不匹配时安装脚本应停止且不修改文件。
- 当前仓库**没有独立运行的汉化插件或运行时 DOM 注入程序**。若计划将静态补丁改造成插件，需先提出架构方案，并说明插件运行环境、加载入口、权限、版本兼容方式、禁用与卸载方式。未确认方案前，不要把新插件与现有安装脚本混为一体。
- 目标是尽可能覆盖固定 UI，同时保持 Pen 功能和用户内容完整。MCP、Hook、Token、API、HTML、CSS、SVG、Figma 等技术词，品牌、模型名、用户输入、设计文档内容、文件路径、字体名称和系统文件选择器应谨慎处理，不做全局替换。

## 2. 双向分工与协作方式

职责是默认分工，不限制另一方提出修复或提交实现。遇到跨边界问题时，由发现问题的一方先给出最小复现、证据和建议，再由另一方复核。

| 工作项 | ZCode 默认负责 | Codex 默认负责 |
|---|---|---|
| 汉化插件架构、插件加载/生命周期、插件自身缺陷 | 设计、实现与插件侧验证 | 审查与 Pen 仓库集成建议；必要时修复仓库适配 |
| 固定 UI 词条、静态资源映射、ASAR 重建 | 提交插件侧需要的词条或兼容要求 | 维护 `patches/static-phrases.json`、`scripts/apply-static-ui.cjs` 及静态补丁路径 |
| 安装、恢复、版本探测、兼容检查 | 提供插件安装/移除需求及版本信息 | 维护 `Install-Chinese.ps1`、`Restore-English.ps1`、`Verify-Compatibility.ps1` |
| Pen 新版本适配 | 若插件依赖该版本，提供插件验证结果与观察到的变化 | 检查归档结构、评估静态补丁影响，并维护仓库支持版本 |
| 文档、复现记录、发布说明 | 记录插件设置、限制、复现与插件版本 | 汇总仓库变更、操作教程、验证证据和风险 |

**双向流转规则：**

1. 任何一方都可以提出任务、实现修复或指出对方交付的问题；另一方需要复核变更及证据，而不是默认接受。
2. 任务要明确目标、当前行为、预期行为、涉及组件/文件、Pen 版本和验收方式。信息不足时，先记录假设并只做不依赖缺失信息的工作。
3. 交接一个任务时，提供变更摘要、文件/提交标识、运行命令、完整结果、未解决问题和下一步。对方复核后，以新增交接记录补充结论，不覆盖历史证据。
4. 同一文件不要并行编辑。需要同时工作时，先按文件或模块划分；跨模块改动先由双方确认接口和词条格式，再分别实现。
5. 推荐在独立分支或提交中交付。合并前检查差异只包含本任务内容；不要把 `app.asar`、原版备份、Pen 安装包、用户设计或密钥加入仓库。

## 3. 仓库入口与职责

| 路径 | 用途 |
|---|---|
| `README.md` | 项目范围、支持版本、安装与恢复入口 |
| `docs/使用教程.md` | 面向使用者的安装、验证和恢复步骤 |

如新增插件，应将其源代码、构建方式、安装/卸载入口和版本兼容策略放入清晰独立的目录，并更新 README 的“当前实现”和“使用方式”。不要静默改变现有静态补丁的行为或支持版本。

## 4. 开发与安全约束

- 修改 Pen 安装目录前，确认 Pen 已完全退出，并保留可验证的原版 `app.asar` 备份；不得覆盖其他版本的备份。
- 新版本适配应从该版本的原始归档开始。先检查结构，再添加白名单和映射；版本未识别、关键文件缺失或校验不匹配时应安全停止。
- 翻译只作用于确认是固定 UI 的文本。不得改动程序分支判断、变量/键名、协议字段、字体识别逻辑、用户画布数据或动态服务端内容。
- 映射要可重复应用且结果稳定。避免依赖前一轮已翻译的文件继续叠加替换；重建始终以匹配版本的原版资源为输入。
- 任何安装器或插件都应明确报告目标版本、修改的文件、备份位置、成功/失败原因；失败时避免留下半写入状态，并提供恢复路径。
- 不提交原版/汉化 `app.asar`、安装包、用户数据、Token、API 密钥、私密截图或机器专属绝对路径。示例日志和截图需先脱敏。
- PowerShell 中文脚本保存为 UTF-8 BOM，避免 Windows PowerShell 的中文编码问题。

## 5. 每个任务的验收清单

按改动范围选择相关项目，未执行的项目应明确标为“未验证”，不可写成通过。

### 静态补丁或词条变更

- 检查词条只命中固定界面，技术标识和动态/用户内容未被误改。
- `node --check scripts/apply-static-ui.cjs` 通过。
- 对实际目标 Pen 资源运行：

  ```powershell
  node scripts/apply-static-ui.cjs --pen-resources "<Pen资源目录>" --check
  ```

- 确认 ASAR 完整性、目标版本、备份和输出状态；启动 Pen 后检查相关界面及基本编辑操作。

### 安装、恢复或兼容变更

- 运行 `Verify-Compatibility.ps1`，确认其只读行为和版本判断符合预期。
- 在可恢复的目标环境中验证安装与恢复；比对恢复后 `app.asar` 与对应原版备份的 SHA-256。
- 对未支持版本确认安装器拒绝修改，并报告清晰原因。

### 插件变更

- 提供插件名称/版本、Pen 版本、加载方式、安装与卸载步骤、权限说明及禁用后的行为。
- 提供插件自己的构建/检查命令和结果，并在真实 Pen 界面验证至少一个成功场景和一个失败/边界场景。
- 若插件调用仓库词条或安装流程，说明接口格式、数据来源和版本兼容约束，并给出与静态补丁并存或互斥的行为。

### 文档或发布变更

- README、教程、支持版本、安装脚本和实际实现保持一致。
- 发布包只含可分发源码、脚本、必要说明和许可证，不含 Pen 本体资源或用户数据。

## 6. 交接消息模板

每次 ZCode 与 Codex 之间移交任务时，复制并填写以下模板：

```text
【任务】一句话描述
【来源】ZCode / Codex
【目标】希望用户最终能做到什么
【Pen 版本与环境】版本、Windows 架构、插件/静态补丁版本
【复现步骤】从干净状态开始的步骤
【实际结果 / 预期结果】
【改动】文件路径、分支或提交标识、实现摘要
【验证】执行的命令、完整结果、手动检查的界面/操作
【风险与未完成项】
【接手方需要做什么】复核、集成、修复或补充验证
```

发现缺陷时附上脱敏截图、精确 UI 路径和最短复现步骤。不要只写“汉化失效”“菜单不对”等无法复现的描述。
